**中断** 是键盘、硬盘等设备向 CPU 发送的信号，用于通知 CPU 暂停正在执行的程序，转而去执行处理该信号的程序。当 CPU 收到特定的中断信号时，会去操作系统提供的 **中断描述符表（IDT）** 寻找 **中断服务程序（ISR）** 处理中断信号。

## 中断分类

- 外中断
    - 可屏蔽中断
    - 非可屏蔽中断
- 内中断
    - 异常
    - 软件中断

### 外中断

外中断是由硬件发起的中断，可以通过 `eflags` 的 `IF` 位屏蔽的属于可屏蔽中断，反之则为非屏蔽中断。

### 内中断

内中断产生于 CPU 和软件，与硬件无关。

#### 软件中断

软件中断是由软件发起的中断，是一种应用程序和操作系统沟通的方式。例如读写磁盘，应用程序运行在较低特权级，无法直接访问硬盘，只能通过操作系统访问。应用程序通过 **系统调用** 通知操作系统执行对应的中断服务程序。

#### 异常

异常是指令执行期间 CPU 内部产生的错误引起的。这些错误会影响 CPU 正常运行，因此不受 `eflags` 中的 `IF` 位影响。

异常按轻重程度可以分为三种：

故障（Fault）：最轻的一种，是可以被修复的，比如缺页异常（Page Fault）
陷阱（Trap）：通常用于调试
终止（Abort）：最严重的异常，无法修复，程序无法继续执行

## 中断描述符表

中断描述符表（Interrupt Descriptor Table，IDT）是 x86 架构下保存中断描述符的表。表的元素称为 **门描述符（Gate Descriptor）**。其结构如下：

```language
|63                                                 48|47 |46 45|44 |43       40|39                       32|
+-----------------------------------------------------+-----------------------------------------------------+
| Offset (16~31)                                      | P | DPL | 0 | Gate Type | Reverse                   |
+-----------------------------------------------------+-----------------------------------------------------+
| Segment Selector (0~15)                             | Offset (0~15)                                       |
+-----------------------------------------------------+-----------------------------------------------------+
```

- Offset：32 位，中断服务程序（ISR）的地址
- Segment Selector：段选择子
- Gate Type：4 位，门描述符的类型
    - 0b0101：Task Gate，Offset 不使用
    - 0b0110：16 位 Interrupt Gate
    - 0b0111：16 位 Trap Gate
    - 0b1110：32 位 Interrupt Gate
    - 0b1111：32 位 Trap Gate
- DPL：2 位，CPU 特权级
- P：1 位，必须为 1

x86 架构支持最多 256 个中断描述符，与 GDT 不同，IDT 的第一项（索引 0）可以使用，这一项通常为 **除零异常**。

## 中断描述符寄存器

中断描述符寄存器（IDTR）保存了 IDT 的地址，其结构如下：

```language
+--------+---------------+
| Offset | Size (16 bit) |
+--------+---------------+
```

- Offset：IDT 的地址，32 位时为 32 位，64 位时为 64 位。
- Size：IDT 的大小减 1

## 中断服务程序

中断服务程序（Interrupt Service Routines）是负责对具体中断进行处理的程序。ISR 并不是 C 函数，因为 ISR 使用中断返回 `iret` 而非普通的 `ret`。

## 相关指令

### lidt 和 sidt

```assembly
lidt <idt_ptr> // 加载 idt_ptr 到 idtr
sidt <idt_ptr> // 保存 idtr 值 到 idt_ptr
```

### int

```language
int <irq> // 调用 irq 号中断
```

中断调用会向栈中顺序压入 `eflags`，`cs`，`eip` 和中断错误码（如果有）。

### iret

`iret` 与 `int` 搭配使用，它会按中断调用的逆序恢复 `eip`，`cs`，`eflags`（不考虑错误码，因此必须特殊处理错误码）。

## 中断处理模块实现

#### IDT

IDT 保存了每个 ISR 的入口地址。

#### ISR

中断发生时 CPU 会顺序入栈 `eflags`，`cs`，`eip`，如果有错误码还会入栈错误码，为了保持栈的结构一致，ISR 需要为没有错误码的入栈一个随机值。除此之外，还需要入栈一个中断向量号以判断执行哪个中断处理函数。

在执行完中断处理函数后，需要将中断向量号和错误码出栈，因为 `iret` 只能处理没有错误码的情况。

因此，一个完整的 ISR 应具有如下功能：

1. 中断发生时顺序入栈 `eflags`，`cs`，`eip`，错误码
2. 若中断没有错误码，则入栈一个值
3. 入栈中断向量号
4. 根据中断向量号执行具体的中断处理函数
5. 出栈中断向量号和错误码
6. `iret` 中断返回
